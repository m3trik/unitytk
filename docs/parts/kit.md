# A kit

**Belongs:** recipes that put several features together for a kind of project, over their public API alone: the one part that may reference more than one feature. `Kits/<Kit>/`: its editor assembly (`M3trik.Unitytk.Kits.<Kit>.Editor`, the recipes: public static methods with an optional `OpContext`, as a feature's actions) and its `Tests/`, nothing else: a kit is editor composition alone, with no runtime part. Types sit in `M3trik.Unitytk.Kits.<Kit>`. **Does not:** change a project except through the features' actions (a recipe asks `ctx` before each change, as an action does), so every component it puts in a scene is a feature's, added by that feature's action; hold a capability a feature could (a component, an importer, an inspector over its own fields, an adapter of one feature's seam to another's: those are a feature's, which the kit then composes); name a client or a project (its content stays in the client's project).

**Extend it by registering, never by editing its loop.** A kit that runs a list of things (a plan's behaviors, a recipe's steps) finds what runs each by an attribute on a class, keyed by name (the manifest's registry reads Unity's index of the types implementing its interface, `TypeCache.GetTypesDerivedFrom<IManifestBehavior>()`, and keeps those carrying the attribute); a project adds its own beside it, in its own assembly. The kit's loop knows no entry by its name: only by what the entry declares (traits on its attribute, interfaces its class implements), so a project's own takes every role the kit's do. The Tasks kit's builders are the example: `[TaskBehavior("use", ActsOn = true)] class UseBehavior : IManifestBehavior`, a gate's builder an `IStepGate`, found by the manifest's registry, with the kit's own part of every build an `IManifestKit` ([the manifest](../manifest.md)).

**Add one:** `python m3trik/scripts/scaffold_unity_part.py kit <Kit>` writes the editor and test assemblies, the recipes class with its `Prior art:` to fill in, and a failing test; reference each feature from the kit's asmdef as the kit starts using it. A contract another language reads (a plan, a manifest) is declared in Python and generated beside the recipes (`m3trik/scripts/sync_unity_contracts.py`).

**Checked by:** the compiler; `check_layers.py` (a kit sits above the tools and features: `Kits/*/Editor` and `Kits/*/Tests` rows of `[tool.m3trik.layers.csharp]`, and no other, so a runtime assembly in a kit is in no declared part); `check_csharp.py` (kernel bypass, prior art, generated files); its Edit Mode tests, each recipe held to the kernel's three checks.

**The kits:** [Tasks](../tasks.md) — the behaviors a task's sheet rows read as, built by the [manifest](../manifest.md).
